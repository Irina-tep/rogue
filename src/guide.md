# Руководство по архитектуре Roguelike игры на Go

## 📐 Общая архитектура (MVC)

Проект построен по принципу **Model-View-Controller** с четким разделением ответственности:

```
Model (Модель данных)      → go/player.go, go/level.go, go/enemy.go, go/object.go
View (Отображение)         → go/render.go
Controller (Логика)        → go/controller.go
Data Layer (Сохранения)    → go/data_layer.go
```

## 🏗️ Основные компоненты

### 1. Модель (Model)

**Центральные структуры:**

- **`Game`** (`main.go`) — главный контейнер состояния игры
- **`Player`** — игрок со статистиками и инвентарем
- **`Level`** — уровень с комнатами, туннелями, врагами, объектами
- **`Tile`** — клетка игрового поля с символами и флагами
- **`Room`**, **`Tunnel`** — генерация карты
- **`Enemy`** — враги с ИИ и характеристиками
- **`Object`** — предметы (еда, зелья, свитки, оружие)

### 2. Представление (View)

**`Renderer`** (`render.go`) — отвечает ТОЛЬКО за отрисовку:
- Не содержит игровой логики
- Получает готовые данные из `Game`
- Отрисовывает окна: игровое поле, статус, сообщения
- Обрабатывает разные состояния игры (меню, победа, поражение)

### 3. Контроллер (Controller)

**`Controller`** (`controller.go`) — ядро игровой логики:
- Обработка ввода пользователя
- Управление перемещением игрока и врагов
- Обновление состояния игры
- Вызов методов сохранения/загрузки
- **Важно:** Вся бизнес-логика должна быть здесь

### 4. Слой данных (Data Layer)

**`SaveManager`** (`data_layer.go`) — управление сохранениями:
- Сериализация/десериализация состояния
- Управление файлами сохранений
- Статистика и таблица лидеров
- **Принцип:** модель не знает о сохранениях, контроллер использует SaveManager

## 🔧 Как расширять код

### Добавление нового типа врага

1. **Добавить константу** в `enemy.go`:
```go
const (
    TileNewEnemy string = "newEnemy"
    ChanceNewEnemy int = 15
)
```

2. **Добавить символ** в `level.go`:
```go
case TileNewEnemy:
    symbol = 'N'  // Символ для отрисовки
```

3. **Расширить генерацию** в `enemy.go`:
```go
var enemyTypes = []EnemyType{
    // ... существующие типы
    {"newEnemy", ChanceNewEnemy},
}
```

4. **Реализовать поведение** в методах `EnemyMove()` и `ChaseTarget()`

### Добавление нового типа предмета

1. **Добавить константу** в `object.go`:
```go
const (
    NEW_ITEM = iota
)
```

2. **Расширить `NewObject()`**:
```go
case NEW_ITEM:
    object.Health = GeneratorNum(5, 15)
```

3. **Добавить символ** в `level.go`:
```go
case TileNewItem:
    symbol = 'N'
    blocked = false
```

4. **Обновить `GetObjectSymbol()`** в `object.go`

### Добавление нового состояния игры

1. **Добавить константу** в `main.go`:
```go
const (
    NewState int = 5
)
```

2. **Обработать в контроллере** (`controller.go`):
```go
if controller.Game.StateGame == NewState {
    controller.HandleNewState()
}
```

3. **Обработать в рендерере** (`render.go`):
```go
} else if g.StateGame == NewState {
    // Отрисовка нового состояния
}
```

## 🚫 Запрещенные практики

### ❌ Нельзя:
1. **Добавлять логику в рендерер** — только отрисовка готовых данных
2. **Помещать обработку ввода в модель** — только в контроллер
3. **Хардкодить параметры в нескольких местах** — используйте константы
4. **Нарушать поток данных**: Ввод → Контроллер → Модель → Рендерер
5. **Изменять `Tile` напрямую** — всегда через `UpdateTiles()`

### ✅ Нужно:
1. **Держать зависимости однонаправленными**:
   ```
   Controller → Model
   Renderer → Model
   Controller → SaveManager
   ```
2. **Использовать конструкторы** (`NewPlayer`, `NewLevel`, etc.)
3. **Хранить игровые константы** в одном месте (верх файлов)
4. **Добавлять новые типы через константы и switch-выражения**

## 📁 Структура файлов и ответственность

| Файл | Ответственность | Зависимости |
|------|----------------|-------------|
| `main.go` | Точка входа, главный цикл | Все компоненты |
| `controller.go` | Вся игровая логика | Model, Data Layer |
| `render.go` | Отрисовка интерфейса | Model (только чтение) |
| `level.go` | Генерация и управление уровнями | Room, Tunnel, Enemy, Object |
| `player.go` | Состояние игрока | - |
| `enemy.go` | Поведение врагов | Room |
| `object.go` | Предметы и их эффекты | - |
| `room.go` | Генерация комнат | - |
| `tunnel.go` | Генерация коридоров | Room |
| `data_layer.go` | Сохранения и статистика | Model |
| `helper.go` | Вспомогательные функции | - |

## 🧪 Тестирование и отладка

### При добавлении новой функциональности:
1. **Проверьте отрисовку** — символы должны появляться корректно
2. **Протестируйте сохранение** — новые данные должны сохраняться/загружаться
3. **Убедитесь в балансе** — шансы появления, характеристики
4. **Проверьте взаимодействия** — как новый элемент влияет на игрока

### Консоль отладки:
Используйте `AddMessage()` для вывода отладочной информации:
```go
controller.Game.AddMessage(fmt.Sprintf("Debug: %v", value))
```

## 🔄 Жизненный цикл изменений

1. **Определите, к какому компоненту относится** (Модель/Вид/Контроллер)
2. **Добавьте данные в модель** (структуры, константы)
3. **Реализуйте логику в контроллере**
4. **Добавьте отрисовку в рендерере** (если нужно)
5. **Протестируйте полный цикл** (ввод → логика → отрисовка)

---

**Ключевой принцип:** Каждый компонент делает ТОЛЬКО свою работу. Модель хранит данные, Контроллер управляет логикой, Рендерер отображает. Соблюдение этой архитектуры гарантирует, что изменения не сломают существующую функциональность.
